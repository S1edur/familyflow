# Family Flow

Сімейний застосунок на двох дорослих: задачі в стилі Linear + домашні гроші.
Усе, що має мету, — проєкт: у ньому задачі й гроші. Модель описана в
`docs/superpowers/specs/2026-09-13-projects-model-design.md`.
Інтерфейс українською, код і назви в базі англійською.

## Стек

React 19 + TypeScript + Vite + Tailwind 4 + react-router (HashRouter).
Компоненти свої, бібліотек UI немає і не додаємо.
Supabase (Postgres + Auth + Realtime) і Vercel (хостинг, функції `api/`, cron).
Усі ключі — у змінних середовища Vercel, у коді й `.env` їх немає.
Без ключів застосунок працює локально на демо-даних у `localStorage`.

## Запуск

```bash
npm run dev                      # http://localhost:5173, --host для телефона
npm run build && node build-single.mjs
```

`build-single.mjs` збирає все в один файл:
- `dist/family-flow.html` — відкривається подвійним кліком
- `dist/artifact.html` — те саме без каркаса, для публікації

`dist` навмисно не чиститься (`emptyOutDir: false`) — у примонтованій теці
видалення може бути недоступне. Скрипт бере найновіші файли за часом зміни.

## Структура

```
src/data/types.ts      типи — дзеркалять схему Postgres
src/data/store.ts      УСЯ доменна логіка: генерація, похідні значення, дії
src/data/links.ts      опис правил людською мовою, маршрути до проєктів і правил
src/data/setup.ts      перші кроки нового дому
src/data/sync.ts       pull / diff-push / realtime; лише змінені колонки
src/data/queue.ts      черга незвантажених змін у localStorage
src/data/cloud-map.ts  колонки ↔ поля; збірка звіряє зі схемою
src/data/auth.ts       вхід, дім, запрошення
src/data/push.ts       підписка браузера на пуші
src/data/seed.ts       демо-дані для локального режиму
src/lib/               гроші, дати, налаштування перегляду
src/ui/                дизайн-система (див. src/ui/README.md)
src/components/        складені компоненти: RuleForm, BillRow, MonthBar…
src/pages/             екрани
api/                   функції Vercel: пуші й ранковий підсумок (cron)
sql/                   міграції по порядку; 03–05 історичні (прибирає 13), 14 — проєкти
scripts/               check-columns.mjs — cloud-map проти схеми
```

**Доступ до даних — тільки через `src/data/`.** Екрани не знають, звідки
беруться дані. Не розтягувати запити до Supabase по компонентах.

## Інваріанти — порушення це баг, навіть якщо екран виглядає правильно

1. **Гроші — це пара**: `amountMinor` (копійки, ціле) + `currency`.
   Ніяких float, ніяких «просто чисел». Форматування — на останньому кроці.
2. **Потік заморожує курс.** Кожен запис зберігає `rateToBase` і
   `amountBaseMinor` на момент створення. Історію ніколи не перераховуємо
   за сьогоднішнім курсом.
3. **Залишки переоцінюються.** Знімки готівки — єдине місце, де курс
   застосовується повторно.
4. **Похідне не зберігається.** Баланс вільних грошей і накопичень, залишок
   боргу, факт проєкту за місяць, «треба відкласти», прогноз, дата закриття —
   усе рахується на читанні. Збережена цифра протухає і мовчки бреше.
5. **Факт проєкту = сума записів.** Не поле для вводу. Ніколи.
6. **Немає «хто кому винен».** `paidBy` існує для питання «ти вже оплатив
   інтернет?» і для балансу навантаження. Взаєморозрахунку між партнерами
   не буде ніколи.
7. **Переказ у накопичення — не витрата.** Запис `transfer` лише перекладає
   гроші між кишенями. Витрата з накопичення — одна витрата цього проєкту,
   без пари «витрата + списання».
8. **`priority === 0` означає «не проставлений» і сортується ОСТАННІМ.**
9. **Повторювана задача в режимі `after_completion` має рівно один
   відкритий екземпляр.** Прострочення не накопичуються.
10. **Пропущений платіж — це статус `skipped`, а не видалення.**

## Правила інтерфейсу

- Підтвердження замість вводу: усе, що має шаблон, — один тап, не форма.
- Порожнє необовʼязкове поле — не поле, а кнопка «додати» (`OptionalFields`).
  Обовʼязкове (назва, сума, проєкт) видиме завжди.
- **Орієнтир на місяць — не ліміт.** Залишок не переноситься й нікуди не
  рухається, перевищення — лише бурштинове порівняння.
- Якщо дві сутності звʼязані, звʼязок видно з обох боків і він клікабельний
  (`src/data/links.ts` + `LinkRow`/`LinkChip`).
- У швидкому записі сума — єдине обов'язкове поле.
- Оптимістичні оновлення, без спінерів на запис.
- **Ніякого червоного «перевитрата» як головного стану.** Перевищення і
  прострочення — бурштинові. Сором це причина, чому такі застосунки кидають.
- Баланс навантаження в діапазоні 40–60% показується нейтрально й без цифр.
- Ніколи не повідомляємо одному, що в другого прострочено.
- Числа: `tabular-nums`, розряди вузьким пробілом, символ валюти після числа,
  копійки тільки коли ненульові.
- Порожній стан пояснює, що тут буде, і дає одну дію. Не порожня сітка.

## Мова

Увесь текст інтерфейсу — українська. Код, назви таблиць, змінні, коментарі
в коді — англійська (коментарі українською допустимі там, де пояснюють
домен). Перший день тижня — понеділок.

## Рішення, які вже прийняті і не переграються без причини

- Усе спільне: обидва бачать і редагують усе. Ролей немає, приховувань немає.
- Транзакційного обліку немає. Регулярне підтверджується чеклістом,
  решта — короткими записами.
- Майстер закриття місяця — ядро, а не додаткова зручність.
- **Усе — проєкти** (рішення 13.09.2026, замінило «проєкт — мітка поверх
  конвертів»). Конвертів, фондів і боргів як окремих сутностей немає: це
  проєкт із напрямом витрачати / накопичувати / повертати / без грошей.
  «Вільні гроші» — системний проєкт, куди падає дохід.
- **Одна витрата — один проєкт.** Витрата в проєкт не створює задачу;
  регулярний платіж сам є пунктом чекліста.
- **Місяць — агрегатор, не сутність**: платежі, скільки відкласти, витрати
  по проєктах і задачі за вибраний місяць.
- **Поповнення проєктів — лише фактичні й вручну.** Застосунок підказує
  суму й дає внести одним тапом; автопоповнень і згенерованих внесків немає.
- Прогнозують люди: очікувані доходи й платежі входять у прогноз місяця.
- Гаманців і рахунків поки немає. Стартовий залишок — надходження у вільні.
- Фото і файли — Supabase Storage, не окремий сервіс.

## Де легко зламати

- **`uid()` і `stableId()` у store.ts — `function`, не стрілки.** Їх викликає
  `materialize()` під час ініціалізації модуля, вище за оголошення.
- **Згенеровані рядки мають детерміновані id** (`stableId`). Другий генератор
  (на сервері чи деінде) мусить рахувати ті самі id, інакше два пристрої
  створять той самий платіж двічі.
- **`projected → due` не синхронізується**: це наслідок календаря, його робить
  кожен пристрій сам. Відправляти — означає затирати оплати партнера.
- **Горизонт повторюваних задач — 7 днів**, у робочих вкладках ховаються
  екземпляри далі ніж на 2 дні. Більше — список тоне в однакових задачах.
- **Seed привʼязаний до сьогоднішньої дати**, інакше «вільно» відʼємне з першого запуску.

## Як працюємо

- Одна фіча — один прохід. Не рефакторити те, чого не просили.
- Після кожної зміни перевіряти складання: `npm run build` (він же звіряє
  cloud-map зі схемою і перевіряє типи `api/`; `tsc --noEmit` бачить лише `src`).
- Нова колонка = нова міграція в `sql/` + поле в `cloud-map.ts`; збірка впаде,
  якщо вони розійдуться.
- Не додавати залежностей без потреби. Дат — тільки власні хелпери в `lib/dates.ts`.
- Не чіпати `src/data/types.ts` без узгодження: це контракт із базою.
