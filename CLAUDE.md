# Family Flow

Сімейний застосунок на двох дорослих: задачі в стилі Linear + домашні гроші.
Інтерфейс українською, код і назви в базі англійською.

## Стек

React 19 + TypeScript + Vite + Tailwind 4 + react-router (HashRouter).
Компоненти свої, бібліотек UI немає і не додаємо.
Дані поки що в `localStorage`; далі — Supabase (Postgres + Auth + Storage).

## Запуск

```bash
npm run dev                      # http://localhost:5173, --host для телефона
npm run build && node build-single.mjs
```

`build-single.mjs` збирає все в один файл:
- `dist/family-flow.html` — відкривається подвійним кліком
- `dist/artifact.html` — те саме без каркаса, для публікації

`dist` навмисно не чиститься (`emptyOutDir: false`) — у примонтованій теці
видалення може бути недоступне. Скрипт бере найновіші файли за часом зміни.

## Структура

```
src/data/types.ts    типи — дзеркалять майбутню схему Postgres
src/data/seed.ts     стартові дані
src/data/store.ts    УСЯ логіка: генерація, похідні значення, дії
src/lib/money.ts     гроші в копійках, форматування, курс
src/lib/dates.ts     дати українською, повторення, «через 3 дн.»
src/components/      примітиви інтерфейсу
src/pages/           екрани
```

**Коли підключатимемо базу — змінюється тільки `src/data/store.ts`.**
Решта коду не знає, звідки беруться дані. Не розтягувати доступ до даних
по компонентах.

## Інваріанти — порушення це баг, навіть якщо екран виглядає правильно

1. **Гроші — це пара**: `amountMinor` (копійки, ціле) + `currency`.
   Ніяких float, ніяких «просто чисел». Форматування — на останньому кроці.
2. **Потік заморожує курс.** Кожен запис зберігає `rateToBase` і
   `amountBaseMinor` на момент створення. Історію ніколи не перераховуємо
   за сьогоднішнім курсом.
3. **Залишки переоцінюються.** Знімки готівки — єдине місце, де курс
   застосовується повторно.
4. **Похідне не зберігається.** Баланс фонду, залишок боргу, факт по
   конверту, «треба цього місяця», дата закриття — усе рахується на читанні.
   Збережена цифра протухає і мовчки бреше.
5. **Факт по конверту = сума записів.** Не поле для вводу. Ніколи.
6. **Немає «хто кому винен».** `paidBy` існує для питання «ти вже оплатив
   інтернет?» і для балансу навантаження. Взаєморозрахунку між партнерами
   не буде ніколи.
7. **Внесок у фонд і виплата з нього — не дві витрати.** У місяці виплати
   показуємо виплату, у місяцях накопичення — внесок.
8. **`priority === 0` означає «не проставлений» і сортується ОСТАННІМ.**
9. **Повторювана задача в режимі `after_completion` має рівно один
   відкритий екземпляр.** Прострочення не накопичуються.
10. **Пропущений платіж — це статус `skipped`, а не видалення.**

## Правила інтерфейсу

- Підтвердження замість вводу: усе, що має шаблон, — один тап, не форма.
- Порожнє необовʼязкове поле — не поле, а кнопка «додати» (`OptionalFields`).
  Обовʼязкове (назва, сума, конверт) видиме завжди.
- Якщо дві сутності звʼязані, звʼязок видно з обох боків і він клікабельний
  (`src/data/links.ts` + `LinkRow`/`LinkChip`).
- У швидкому записі сума — єдине обов'язкове поле.
- Оптимістичні оновлення, без спінерів на запис.
- **Ніякого червоного «перевитрата» як головного стану.** Перевищення і
  прострочення — бурштинові. Сором це причина, чому такі застосунки кидають.
- Баланс навантаження в діапазоні 40–60% показується нейтрально й без цифр.
- Ніколи не повідомляємо одному, що в другого прострочено.
- Числа: `tabular-nums`, розряди вузьким пробілом, символ валюти після числа,
  копійки тільки коли ненульові.
- Порожній стан пояснює, що тут буде, і дає одну дію. Не порожня сітка.

## Мова

Увесь текст інтерфейсу — українська. Код, назви таблиць, змінні, коментарі
в коді — англійська (коментарі українською допустимі там, де пояснюють
домен). Перший день тижня — понеділок.

## Рішення, які вже прийняті і не переграються без причини

- Усе спільне: обидва бачать і редагують усе. Ролей немає, приховувань немає.
- Транзакційного обліку немає. Регулярне підтверджується чеклістом,
  решта — короткими записами.
- Майстер закриття місяця — ядро, а не додаткова зручність.
- Проєкти (ремонт, подорож) — наскрізна мітка поверх конвертів із власним
  бюджетом, а НЕ другий конверт. Витрата належить конверту, проєкт — це
  додаткова необов'язкова прив'язка.
- Фото і файли — Supabase Storage, не окремий сервіс.

## Як працюємо

- Одна фіча — один прохід. Не рефакторити те, чого не просили.
- Після кожної зміни перевіряти складання: `npx tsc --noEmit` і `npm run build`.
- Не додавати залежностей без потреби. Дат — тільки власні хелпери в `lib/dates.ts`.
- Не чіпати `src/data/types.ts` без узгодження: це контракт із майбутньою базою.
