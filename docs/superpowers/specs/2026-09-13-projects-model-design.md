# Усе — проєкти: модель і план реалізації

Дата: 2026-09-13. Концепт із вайрфреймами: `docs/private/projects-concept.html` (локально).
Замінює рішення «проєкти — мітка поверх конвертів».

## Рішення (затверджені Денисом)

1. **Одна сутність — проєкт.** Конверт, фонд і борг зникають. Задачі бувають без проєкту (побут) або в проєкті.
2. **Одна витрата — один проєкт.** Витрата в проєкт не створює задачу; платіж за розкладом сам є пунктом чекліста (не пара «задача + витрата»).
3. **Ліміт на місяць — орієнтир, не обмеження.** Залишок не переноситься й нікуди не рухається; перевитрата — лише бурштинове порівняння з орієнтиром.
4. **Прогноз, а не лише факт.** Очікувані доходи й платежі входять у прогноз місяця — планують люди.
5. **Поповнення проєктів — лише фактичні, вручну.** Застосунок показує, скільки треба відкласти; людина вносить одним тапом із передзаповненою сумою. Автопоповнень і згенерованих внесків немає.
6. **Регулярні платежі — пункти чекліста**, які людина підтверджує. Автоматизації — пізніше.
7. **Місяць — агрегатор**, не сутність: платежі, задачі, скільки відкласти, витрати по проєктах за вибраний місяць.
8. **Гаманців/рахунків поки немає.** Стартовий залишок — надходження у «Вільні гроші».
9. **Групування проєктів** за напрямом; завершені згорнуті.

## Модель даних

### Project
| Поле | Тип | Суть |
|---|---|---|
| id, name, description? | | |
| direction | `'spend' \| 'save' \| 'repay' \| 'none'` | витрачати · накопичувати · повертати · без грошей |
| status | `'active' \| 'done' \| 'archived'` | |
| isFree? | boolean | системний «Вільні гроші», рівно один на дім |
| currency | Currency | |
| startsOn?, endsOn? | ISO date | endsOn порожнє = безстроково |
| targetMinor? | number | save: зібрати · spend: бюджет на весь час · repay: тіло боргу |
| monthlyMinor? | number | spend: орієнтир на місяць · save: фіксований внесок · repay: платіж на місяць |
| bufferPct? | number | save: запас до цілі |
| counterparty? | string | repay |
| sourceProjectId? | ID | spend/repay: з якого накопичення платимо (порожнє = вільні) |
| ownerId? | ID | особистий проєкт |
| sortOrder, pinned? | | |

### Entry (запис)
`kind`: `'income' | 'expense' | 'transfer' | 'repay'`
- **income** — ззовні → `projectId` (порожнє = вільні)
- **expense** — `projectId` → назовні
- **transfer** — `fromProjectId` (порожнє = вільні) → `projectId` (порожнє = вільні). Не витрата.
- **repay** — `projectId` (borg) → назовні, залишок боргу меншає

Решта полів як були: сума, валюта, заморожений курс, дата, `occurrenceId`, `tripId`, нотатка, автор.

### RecurringPlan
`envelopeId`, `fundId`, `debtId` → `projectId` + `flow: 'in' | 'out'`. Ефект оплати визначає проєкт: in → income; out → repay для repay-проєкту, інакше expense.

### Occurrence
`envelopeId`, `fundId` → `projectId`. Внески у фонди більше не генеруються.

### Task, TaskTemplate, Trip
`+ projectId?`

### Прибирається з клієнта
Envelope, PlanLine, Fund, Debt (таблиці в базі лишаються порожньою історією).

## Похідні значення (нічого не зберігається)

**Куди «лягає» запис** (`bucketOf`):
- income → `projectId ?? free`
- transfer → з `fromProjectId ?? free` у `projectId ?? free`
- expense/repay у проєкт P → якщо P.direction = save, то P; інакше `P.sourceProjectId ?? free`

**Баланс кошика** (free або save-проєкт) = надходження + перекази в − перекази з − витрати й погашення, що лягають на нього.

**spend-проєкт за місяць**: факт = витрати з `projectId = P` за місяць; орієнтир = `monthlyMinor`; очікуване ще = відкриті платежі P цього місяця; для строкових — всього витрачено проти `targetMinor`.

**save-проєкт**: баланс; ціль із запасом; місяців до `endsOn`; треба на місяць = `monthlyMinor` або `ceil((ціль − баланс) / місяців)`; внесено цього місяця = перекази в P за місяць; відкласти ще = max(0, треба − внесено).

**repay-проєкт**: сплачено = погашення P; залишок = `targetMinor − сплачено`; прогноз закриття = залишок / `monthlyMinor`.

**Прогноз вільних на кінець місяця** (лише для поточного й майбутніх):
`вільні зараз + очікувані доходи місяця − для кожного spend/repay без джерела: max(орієнтир, факт + відкриті) − факт − відкласти ще по save-проєктах`.

## Екрани

| Маршрут | Що |
|---|---|
| `/` Сьогодні | вільні зараз і прогноз, мої задачі й платежі, рух до цілей, перші кроки |
| `/tasks` Задачі | як зараз + чип «Проєкт» у задачі, фільтр за проєктом |
| `/projects` Проєкти | «Вільні гроші» вгорі; групи: витрачати · накопичувати · повертати · без грошей; завершені згорнуті; створення з шаблону |
| `/projects/:id` Проєкт | шапка з прогресом; вкладки Гроші · Платежі · Задачі · Налаштування; дії Внести / Витратити / Сплатити |
| `/month` Місяць | прогноз, «відкласти» по save-проєктах з одним тапом, чекліст платежів, spend-проєкти факт/орієнтир, борги, задачі місяця |
| `/shopping`, `/history`, `/settings` | проєкт замість конверта |

Старі маршрути `/envelopes`, `/bills`, `/funds`, `/debts`, `/month?tab=…` перенаправляються.

## Шаблони проєктів
Щоденні витрати · Регулярні платежі · Ціль · Запас · Борг · Разовий бюджет · Особисті · Без грошей — лише передзаповнюють поля.

## Міграція (`sql/14_projects.sql`)
- `projects` + RLS + `updated_at/deleted_at` + тригер + realtime.
- «Вільні гроші» на кожен дім.
- Конверт (не дохід) → spend-проєкт з тим самим id; орієнтир = останній план; накопичувальні/борги/заощадження → архів.
- Фонд → save-проєкт з тим самим id. Борг → repay-проєкт з тим самим id.
- `entries.kind` → text + check; income → вільні; fund_in → transfer; fund_out у парі з витратою → зливається у витрату проєкту-фонду; одиночний fund_out → expense проєкту-фонду; debt_payment → repay.
- `occurrences.project_id`, незроблені внески фондів → мітка видалення.
- `recurring_plans.project_id`, `flow`; `tasks`, `task_templates`, `shopping_trips` → `project_id`.
- Клієнт: ключ локального сховища → `familyflow.v2`, черга старого формату очищається.
